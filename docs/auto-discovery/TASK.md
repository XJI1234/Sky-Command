# 手机免手动连接任务说明

更新日期：2026-10-13。状态：当前位置网络初测完成，公告协议及生命周期接线方向已确定，正式功能实施中；手机自动发现尚未实现。

## 要解决的问题

当前手机需要填写电脑的 WebSocket URL，再点击“保存并启动”。电脑更换网络或 DHCP 地址变化后，手机保存的地址可能失效。路由器固定分配地址不能解决更换网络后的发现问题。

目标是让 Sky Command 自动公布可用连接地址，MSDK Relay 打开后自动发现并连接。日常使用减少到“打开手机 App”；首次安装时 Android 的权限确认仍须由用户完成。

## 已确定的任务范围

| 事项 | 决定 |
| --- | --- |
| 系统规模 | 一台电脑，多个手机；每个手机管理一个遥控器及其无人机 |
| 优先网络 | 电脑与手机都通过无线连接当前校园 Wi-Fi |
| 当前方案级别 | 第一阶段最小方案，不是完整的跨网络发现方案 |
| 电脑离线 | 手机低频等待；电脑重新上线后自动发现并连接 |
| 手机操作 | 授权后打开 App 自动运行；计划移除“停止中继”按钮 |
| 航线范围 | 不扩展航线规划，也不修改现有航线、飞行及任务退出行为 |
| Git 记录 | 分仓库、开发分支、中文提交；最终通过 GitHub 分支和 PR 分享 |
| 发现冲突 | 已连接时保持当前电脑；未连接且发现多个候选时显示冲突并等待，不自动选第一台 |
| 第一版接入 | 沿用现有未认证 v1 协议进行受控联调；正式开放前再补可信接入 |
| 首轮验收规模 | 2 台手机、2 架无人机；目前网络实测只有 1 台手机，遥控器型号仍待补充 |
| 后台/锁屏 | 已授权后继续中继，划掉任务卡片也继续；电脑退出后继续等待，保留系统前台通知 |
| 自动恢复边界 | 不做开机自启，不承诺系统强制停止后自行恢复 |
| 调试入口 | 保留隐藏的手动地址调试入口；日常连接不依赖它，主界面不保留停止中继按钮 |
| 连接耗时目标 | 已授权且两端服务就绪后 15 秒内连接；手机先开从电脑服务就绪计时，超时记为验收失败并继续等待 |

以上后台/锁屏行为和 15 秒目标已由用户确认，仍需实现后实机验收，不是已验证结果。系统杀进程或强制停止不作为可保证自行恢复的场景；再次打开 App 后应重新进入正常流程。

## 涉及哪些仓库

- Sky-Command：电脑端发现公告、网卡及监听状态接线、发现诊断。
- MSDK-Relay：Android 接收、自动发现与连接协调、权限/前台服务/界面接线。
- MSDK：独立 HTTP 示例，当前任务不改其业务源码。

组长说明对频按钮迁移由另一位开发者处理；当前本地 MainActivity 仍有两个对频按钮。需要核对对方所在分支及迁移接口，避免重复修改。本任务不自行扩展对频功能。

## 预期验收

1. 已授权手机打开 App，不填地址、不点连接即可接入电脑。
2. 手机先开或电脑先开，最终都能自动建立现有协议会话。
3. 多台手机各自连接，不混用设备身份或会话。
4. 电脑重启、IP 变化和 Wi-Fi 重连后能重新发现；连接正常时不因重复公告反复重连。
5. 重连不重放旧命令、旧文件传输，不新增飞行动作。
6. 当前校园 Wi-Fi 的广播送达和手机到电脑的 WebSocket 可达均有实测证据。
7. 首次权限拒绝、未发现电脑、连接失败有可读状态；手机后台/锁屏行为有实机记录。
8. 使用 2 台手机/2 架无人机验收；已授权且服务就绪后 15 秒内建立连接，超时记录失败，不把持续等待视为达标。

网络限制若使广播无法工作，应记录原因并重新讨论方案；不能把已授权且“零手动连接”的目标悄悄降级为要求用户手填地址。
