# 2026-10-14 正式 Relay 单手机实机调试

一台 Windows 电脑、一台小米 10 / Android 13；Relay 源码为 `c8b4c16`。Debug APK SHA-256：`9DFD7E37FE5940B3EF558D31C6658CAF5E0E1B38DCBB5912D0A41CE1C496C468`。先测试原校园 Wi-Fi，之后按用户选择，两端接入另一部手机提供的热点进行对照。USB 仅用于 ADB 安装和诊断，发现及电脑连接仍走 Wi-Fi；手机 USB 未连接遥控器，没有发送飞行/航线命令。

## 观察与结果

| 检查 | 结果及范围 |
| --- | --- |
| 无线 ADB | 两轮当前配对信息均失败，配对返回协议错误；指定连接端口超时，直接 TCP 检查也未建立连接 |
| USB 安装 | 本人手机授权 USB ADB；install -r 返回 Success，更新安装时间已核对 |
| 无地址自动运行 | MainActivity 冷启动成功，显示“运行时：运行中”“电脑连接：搜索电脑，等待上线”；没有填写地址或点击启动。手机已有授权，不覆盖全新授权/拒绝恢复 |
| SDK | 界面显示“MSDK 生命周期：已就绪”；不代表遥控器、飞机、图传或账号已验收 |
| 前台服务/界面往返 | dumpsys 显示一个 RelayForegroundService，isForeground=true，foregroundId=1001；单次返回桌面后原 App 进程及服务保持，重新打开为 HOT，继续搜索 |
| 电脑服务/公告 | 重建并启动成功，8080、19500、18080 监听；重连后电脑本机收到 4 个正式 UDP 39082 公告，均 224 字节、指向 8080/relay。不证明手机收到广播 |
| 校园网重连 | 两端断开再连原校园 Wi-Fi，确认同一 SSID、同一 AP、同一 /17 子网；两端地址没有改变 |
| 设备间互通 | 重连前后均返回目标主机不可达，电脑没有手机 ARP 记录，手机到电脑也不可达；具体隔离/接入策略尚未确认 |
| 校园网正式自动连接 | 手机持续数分钟搜索，没有观察到 paired/已连接；校园这一轮 15 秒目标未达标，没有报告精确首包或连接延迟 |

手机持有 relay-discovery MulticastLock。Android 对 ss/netlink 的权限限制使本轮无法据命令输出核实 UDP 监听端口或收包计数，不把空输出记作“0 包”或“未监听”。当前 Relay PID 的定向 MSDKRelay/AndroidRuntime 错误检查未见新崩溃；其他 App 的旧日志不作为本版本错误证据。

## 校园网阶段结论

安装、已有授权下无地址运行、前台服务及单次界面往返已有实机证据。校园网重连未解决设备间互通；当前阻塞在网络路径，不能仅据此认定生产接收器有缺陷。

校园网后续需要核查同 AP 终端互通和接入策略，网络恢复后复测正式 39082、二进制 hello/paired 和 15 秒目标。没有改变防火墙、静态路由或校园网配置。用户随后选择热点对照与 USB 调试，结果如下。

## 热点对照：正式自动连接及重连

小米 10 和电脑均作为同一独立手机热点的 Wi-Fi 客户端；双方为同一 /28 子网。手机仍为原 App 进程，未重装、未填写手动地址，也未重建业务图。USB ADB 保持连接。

| 场景 | 观察与证据 | 结果 |
| --- | --- | --- |
| 校园网切换到热点 | 手机热启动后显示“电脑连接：已连接”；电脑 8080 TCP 为 Established，日志新增 DEVICE_PAIRED（北京时间 19:26:37） | 正式 AUTO/hello-paired 路径通过一次；首次切换未提前开始计时，不报告首次连接延迟 |
| 热点 Wi-Fi 断开再连 | USB 执行手机 Wi-Fi 关闭/开启；从开启命令执行前开始计时，5.94 秒观察到新 TCP，8.67 秒采样到“已连接”；日志先 DEVICE_UNPAIRED 后 DEVICE_PAIRED | 本轮在 15 秒内；原进程与前台服务保留 |
| 返回手机桌面 | Launcher 在前台，Relay 服务仍 isForeground=true，电脑仍有同一手机 Established 会话，重新打开 App 仍连接 | 短时后台/界面往返通过一次；不外推长期后台、锁屏或划卡 |
| 电脑正常退出 | 用户关闭窗口，8080/19500/18080 均停止监听；手机 HOT 打开仍“运行中 / 搜索电脑，等待上线”，原进程/服务保留 | 等待电脑重新上线通过一次；无遥控器/无人机，不覆盖活动航线退出 |
| 电脑重新启动 | 有效重启命令开始后 8.04 秒观察到 8080 监听、11.63 秒观察到 TCP、14.17 秒采样到“已连接”；电脑日志新增 DEVICE_PAIRED（北京时间 19:57:07） | 本轮在 15 秒内；时间包含 npm/Electron 启动与界面采样，不是精确配对时刻 |

两次计时均从恢复/启动命令之前开始，包括网络或服务准备和 UI 采样，作为保守上界，不能推广为校园网或多设备的稳定保证。电脑重启前的一次沙箱启动因 Electron 用户目录锁/IPC 拒绝访问未启动服务；按环境权限机制重试后成功，上表记录有效重试，不将服务未就绪的工具失败混作协议重连失败。

热点下电脑 ping 手机成功，手机 ping 电脑仍未回复，但实际 WebSocket/paired 成功；ICMP 不能代替业务连接证据。无线 ADB 在网络切换后未恢复，用户明确先使用 USB 调试，未继续配对或启用旧式 TCP 5555。

当前结论：正式源码的单手机自动发现、网络换代、电脑离线等待及重新上线路径在本次热点环境已有实机成功证据；校园网仍受设备间互通阻塞，整体校园网验收未通过。后续电脑端启动交由用户手动操作。全新权限/拒绝恢复、锁屏、划卡、长期后台、多电脑冲突、电脑 IP 再变化、跨 AP、2 手机/2 无人机、真实飞行/航线/图传仍待验收。
