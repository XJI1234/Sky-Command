# 局域网自动发现公告 v1 契约

更新日期：2026-10-13。本契约固定第一阶段两端实现参数；是否已实现/验收以 PROGRESS.md 为准。公告只用于发现，不提供认证，不改变 WebSocket 二进制 hello/paired 协议。

## 数据报

- 手机监听 UDP IPv4 **39082**；39081 保留给独立网络探针。电脑绑定实际 WLAN IPv4 的随机源端口，手机不校验 UDP 源端口。
- 一包一条 UTF-8 JSON 对象，最大 **512 字节**。手机使用至少 513 字节接收缓冲，超过 512、截断、非法 UTF-8、非法 JSON 或字段校验失败直接丢弃，不据此创建连接或刷新缓存。
- 必须字段如下，允许忽略大小限制以内的未知扩展字段；不允许字段类型强制转换。

| 字段 | 类型与规则 |
| --- | --- |
| kind | 字符串，精确等于 `SKY_COMMAND_RELAY_ANNOUNCEMENT` |
| discoveryVersion | JSON 整数，精确等于 `1` |
| serverId | 小写 UUID；随机生成并保存在电脑应用数据目录，重启沿用；非设备硬件标识 |
| instanceId | 小写 UUID；每次电脑进程启动随机生成，不持久化 |
| protocolVersion | 字符串，精确等于 `1`，对应现有 WebSocket v1 |
| relayPort | JSON 整数，范围 1–65535；当前正式服务为 8080 |
| relayPath | 字符串，精确等于 `/relay` |

合法示例（身份仅为测试值）：

```json
{"kind":"SKY_COMMAND_RELAY_ANNOUNCEMENT","discoveryVersion":1,"serverId":"11111111-1111-4111-8111-111111111111","instanceId":"22222222-2222-4222-8222-222222222222","protocolVersion":"1","relayPort":8080,"relayPath":"/relay"}
```

不发送 host、完整 URL、手机 deviceId、sessionId、密钥或墙上时间。手机使用数据报的合法单播 IPv4 来源构造 `ws://<来源IPv4>:<relayPort>/relay`，拒绝回环、未指定、组播及广播来源。不信任负载提供的地址，不做校园网扫描。身份与来源都可伪造，仅供已确认的受控联调。

## 电脑发送规则

1. 仅在 DesktopApplication.start 成功（含 WebSocket 监听成功）后启动公告；失败不公告。
2. 每 **1 秒**重新读取网卡；仅使用名称匹配 Wi-Fi/WLAN/Wireless/无线的非虚拟、非内部、RFC1918 IPv4 网卡。Tailscale、VPN、虚拟机网卡不用于本阶段广播；旧的手动连接能力不受影响。
3. 根据当前 IPv4 与连续子网掩码计算定向广播；仅接受 /1–/30 子网，不用“末字节改 255”。每个地址绑定一个 UDP socket，绑定完成立即向定向广播和 `255.255.255.255` 各发一包，此后每秒重复；两目标相同则只发一包。
4. 地址/掩码消失或改变时先关闭旧 socket，再创建新 socket；无 WLAN 时暂停发送，持续低频检查。绑定/发送失败只记录限频诊断并重试，不终止桌面应用。
5. 退出开始时先停止公告和检查定时器，再沿用既有桌面退出流程；不新增或改写飞行、航线指令。停止后迟到的绑定/发送回调不得恢复公告。

一秒周期用于当前丢包环境下的初版重复公告，不是可靠性或 15 秒达标保证。协议不含 TTL，手机过期时间由本地单调时钟计算。

## 手机候选与选择规则（待实现）

- 候选键为 `(serverId, instanceId)`，同一实例的两个广播和重复包合并。来源 endpoint 分别保存接收时间，以最近有效公告为准；同一时刻用 IPv4 字典序保证选择确定。
- 每个 endpoint 在最后有效接收 **8 秒**后过期；候选无存活 endpoint 时删除。电脑重启的新 instanceId 是新候选，旧实例自然过期。
- 未连接时，收到首个有效候选后至少观察 **3 秒**。观察结束只有一个存活候选才连接；两个及以上显示冲突并等待。冲突消退为一个后重新观察 3 秒。缓存上限 32 个候选；超过上限进入冲突等待，直到已缓存候选全部过期并重新观察，不能因容量限制静默选择第一台。
- ACTIVE 时固定当前电脑和 endpoint。重复公告、第二台电脑、新 instanceId 或公告过期都不打断健康会话；握手成功才算已连接。
- 丢失 ACTIVE 后先清理旧代次。若候选冲突或无存活候选，暂停旧 endpoint 的自动重试并等待；唯一候选通过观察窗口后才启用/更新 endpoint。相同 endpoint 的连接失败沿用现有 1/2/4/8/16/30 秒退避；重复公告不调用 start、不重置退避。
- endpoint 更新、暂停重试必须在线性化的 connection-session 事件序列中执行，并保留旧代次隔离、命令/传输清理与单一连接约束。这是下一阶段需要补齐的 gateway/session 契约扩展，当前 API 不具备此能力；不能用关闭并重建 MobileRelayGraph 代替。
- Wi-Fi 切换清空旧网络候选、关闭旧监听、使旧回调失效；在新 Wi-Fi 网络重新绑定监听并进入观察。健康会话不因单纯重复网络通知重建；实际网络丢失后由 transport 结束会话。

## 实现验证与实机验收

电脑自动化验证覆盖数据格式、真实子网广播计算、网卡排除、周期重复、地址替换、绑定/发送失败恢复、退出及迟到回调；手机另测大小/字段校验、观察窗口、过期/冲突、网络代次和 endpoint 切换。双端公告编码/解码必须使用上面的共享示例。

最后按 TASK.md 使用 2 手机/2 无人机验证后台、锁屏、划掉任务卡片、启动顺序、电脑重启/IP 变化、Wi-Fi 重连与跨 AP；15 秒目标必须以正式 Relay 的合法 paired 计时。自动化测试和探针成功都不替代这项验收。
