## 什么进入源码分支

| 内容 | 处理 |
| --- | --- |
| 本次修改的源码、必要应用资源、接口契约 | 提交，保留原有模块结构 |
| 验证行为所需的测试或网络探针源码 | 提交；当前包含电脑 scripts/send-network-probe.ps1、手机 tools/network-probe 独立 App 及脱敏 NETWORK-RESULTS.md |
| package.json、package-lock.json、Gradle 构建脚本与 wrapper | 提交，供他人安装和复现；wrapper JAR 等必要构建文件不因是二进制就排除 |
| 通用启动文档、任务/设计/进度、脱敏验证结论 | 提交；地址使用占位或动态输入，路径以使用者环境为准 |
| 不含真实密钥的配置模板 | 提交，例如 MSDK 的 gradle.properties.example；填写后的本地配置不提交 |

Relay 已跟踪的 `gradle.properties` 是公共构建配置，应保留且不得填入密钥。Relay 的 DJI Key 使用开发者自己的用户级 Gradle 配置；MSDK 填写后的仓库内 `gradle.properties` 已被忽略。不要把两个文件混为一谈。新增 `gradle.local.properties` 的忽略规则只防止误提交，不代表 Gradle 会自动加载这个文件。

## 什么不进入源码分支

| 内容 | 留在哪里 / 原因 |
| --- | --- |
| DJI Key、GitHub token、ADB 配对码、签名私钥、keystore 和真实 .env | 各开发者本机；不写入代码、文档、提交消息、截图或 PR |
| local.properties、本机 SDK/JDK 路径及填写后的秘密配置 | 本机配置；通用文档说明配置方法即可 |
| node_modules、.gradle、.kotlin、build、dist、生成的 Electron 入口、安装包 | 本机依赖/缓存/输出；使用依赖声明和构建脚本复现 |
| APK/AAB、桌面 EXE 安装包、打包目录 | 如需给使用者安装，单独交付构建产物，不加入源码提交 |
| 原始运行日志、logcat、截图、真实设备标识、照片、航线及现场测试数据 | 本机；必要的验证证据先脱敏，再选择性提交结果或人工检查后的附件 |
| 工作区父目录 START-HERE.md、AGENTS.md | 本机文件，不属于三个子仓库；给其他开发者的启动说明在各仓库 docs/LOCAL_DEVELOPMENT.md |

本地照片或航线等数据不能依赖扩展名一概忽略：项目也可能有合法的图片资源、测试航线。应放入已有被忽略的临时/数据目录，并在暂存时检查具体文件。本说明列出交付规则，不能代替对内容的检查。

## 分支会不会影响原代码

推送开发分支会在远端增加分支和提交记录；只有合并 PR 才会将这些改动引入目标 main。本次不直接推送 main、不强制推送、不改写原始历史。公开仓库里的开发分支也公开可见，分支不是隐私隔离措施。

Git 推送传输分支可达的提交历史，不会上传整个本机文件夹。未跟踪/被忽略的本机依赖不会自动上传；已经跟踪的文件不会因新增 .gitignore 规则自动停止跟踪。不要使用 `git add .` 或 `git add -f` 批量加入本机文件。

当前早期文档提交曾记录本机局域网 IP/掩码，本次已从最新文档移除；这些非密钥信息仍存在于旧提交，推送本分支时旧提交也会可见。如交付要求连历史中的这些信息也不能公开，应在推送前另行整理分享分支并复核，不能声称本次新增忽略规则已清除历史。

## 分享前与分享时

1. 在每个准备交付的仓库确认分支及 `git status --short`；查看 `git diff main...HEAD --stat` 和完整差异，确认只包含所需变化。
2. 精确暂存本次文件，查看 `git diff --cached --name-status` 与完整暂存差异，检查密钥、个人路径、设备标识及产物。用 `git check-ignore -v <本地文件路径>` 检查排除原因；它不能证明已跟踪文件安全。
3. 运行与改动相关的检查；中文提交标题与正文记录目的、改动、验证及未验证范围。自动发现未验收时明确标为方案或开发中。
4. 确认分享范围后，在各仓库分别运行下面的命令，再创建对应 Draft PR；实际执行结果以 PROGRESS.md 为准。

   ```powershell
   git push -u origin dev/local-startup-20261012
   ```

5. PR 中填写配套 PR/分支链接、拉取构建方法、验证证据与仍待解决事项。不要将本机工作区文档跨目录链接当成 GitHub 可访问链接。

若后续需要 APK/Windows 安装包，可通过 GitHub Release 附件或约定渠道交付，并注明对应仓库提交、版本、构建方式、SHA-256、安装与验证范围。调试 APK 与正式签名包的用途要区分；Android 包可能嵌入 DJI 应用 Key，上传 APK 前也须检查，不因源码没提交 Key 就认定安装包不含 Key。当前没有发布安装包或 Release。
