# 确认降落判断修复（2026-10-16）

10 月 2 日 `d13bb23` 新增的监控页把 `CONFIRM_LANDING` 飞行模式与原始确认请求标志等同。实际记录中存在模式为 `CONFIRM_LANDING`、`landingConfirmationNeeded=false` 且飞机继续下降的反例，因此不能由该模式决定发送 `KeyConfirmLanding`。

## 本次修复

- 只有原始 `landingConfirmationNeeded === true` 才显示并选择确认降落；该模式本身仍按降落过程显示，保留停止自动降落入口。
- 页面检查、创建确认请求及消费确认后实际发送前，均检查确认请求是否存在。false、未知、缺失或请求期间变为 false 时不发送确认命令。普通人工降落不受该标志阻断。
- 保留 DJI onSuccess 原始回执，补充实际下降/落地须看飞控状态的说明。监控页直接飞行成功显示“已受理”。
- SDK 本地版本更新为 0.2.4，云端本地依赖及锁文件已更新；经用户确认飞机落地停桨后重启本地网关。
