# 电脑端对频测试

本次改动仅位于两个仓库的 `feature/desktop-pairing-control` 分支和 `.worktrees/desktop-pairing-control` 目录。

- Sky-Command 基于 `d13bb23`，设备页新增开始对频、停止对频，经白名单 IPC、工作流、对频控制器和 Relay 适配器下发。
- MSDK-Relay 基于 `5daf918`，手机删除这两个按钮，保留现有命令处理和对频状态显示。
- 本测试分支没有合入照片回传分支 `aae906b`，也没有带入主目录的未提交 WHIP 试验改动。

## 测试入口

桌面快捷方式为 `Sky Command 2`，指向本工作树的已构建程序。测试前关闭其它 Sky Command 窗口；各版本共用启动锁及服务端口。

1. 打开 Sky Command 2，在手机启动中继并连接电脑。
2. 在电脑设备页选择手机。新增飞机或更换遥控器时使用开始对频。
3. 开始要求手机端 MSDK 就绪、遥控器已连接、飞控未明确连接。飞控回报未知也允许开始，与手机端原有规则一致；正在对频时阻止重复开始，停止后可以再次开始。停止按钮依据手机回报的对频状态开放。
   两个按钮下方会直接显示可操作状态或禁用原因。若飞机已自动连接，开始对频显示“飞控已连接，无需对频”；检查按钮开放时，可关闭飞机、保留遥控器和手机中继连接，飞控回报未知或断开后刷新状态。
4. 命令成功只代表手机确认本次调用，最终对频状态仍以手机遥测显示为准。

## 已完成验证

桌面类型检查、构建以及对频相关契约测试通过；手机应用测试和清单检查通过，测试 APK 已生成并通过无线调试覆盖安装。

已在运行中的 Sky Command 2 确认：MSDK 就绪、遥控器已连接、飞控回报未知时，开始对频按钮可点击。真机日志记录开始和停止命令均被手机接受，对频状态经历 PAIRING、STOPPING、IDLE，之后飞控已连接；尚未收到本次重新绑定成功的 PAIRED 确认。

测试时另观察到图传和照片回传问题，本次改动未修复这些问题，也不包含 Sky Command 1 的独立优化。
